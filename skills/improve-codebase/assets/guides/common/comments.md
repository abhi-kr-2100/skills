# Comment Quality

- **Don't Comment Bad Code—Rewrite It:** Comments should not be used as a crutch for poorly written code.
- **Explain "Why", Not "What":** The code should explain "what" it is doing. Comments should explain the reasoning or intent behind it.
- **Avoid Obvious Comments:** Don't write comments that simply restate what the code clearly says.
- **Warning of Consequences:** Use comments to warn other developers about potential pitfalls or side effects of a piece of code.
- **TODO Comments:** Use TODO comments for tasks that need to be done but can't be done right now.
- **Documentation Comments:** Provide clear documentation for public APIs, including parameters and return values.
